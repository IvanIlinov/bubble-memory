# ТЗ: Bubble Memory — Telegram Mini App (v3 — финализированная механика)

> Эта версия фиксирует решения, принятые по открытым вопросам из v2. Ниже — сначала changelog, потом полный текст ТЗ с учётом решений.

## Changelog (что изменилось относительно v2)

1. **Механика повторения — чистый трекинг.** Никакого банка заданий, никакой проверки ответов. Клик по пузырю-заданию = засчитанное повторение, +1 к недельному пузырю. Задача становится проще, честнее по объёму работы и остаётся в духе «10–30 секунд».
2. **Роль преподавателя / админка — не реализуется в MVP.** Профили открыты всем публично, «в гости» может зайти любой пользователь — отдельная система прав доступа не нужна на этом этапе.
3. **Рейтинг — публичный**, с возможностью задать себе уникальный никнейм (не обязательно совпадающий с Telegram-username).
4. **Границы недели/месяца/года — календарные** (ISO-неделя пн–вс, календарный месяц, календарный год).
5. **Числовые пороги цвета памяти и тиров эволюции — утверждены** как в черновике (см. ниже), с пониманием, что это конфиг, а не хардкод, и его можно будет менять.
6. **Хостинг — в РФ.** Подтверждено как требование.
7. **Экран согласия на обработку персональных данных** — необходим, но не приоритет сейчас: продукт пока для внутреннего использования. Реализуется последним, обязательно перед публичным запуском.
8. **Реализация Telegram-интеграции (валидация initData, бот-фреймворк, уведомления, cron)** — принимается как предложено в v2, без дополнительных уточнений.
9. **Технологии — уточнены версии окружения:** Node.js v22.22.2, npm 10.9.7, npx 10.9.7.
10. **Дизайн — игровой, погружающий** (направление зафиксировано, детали — на этапе визуального дизайна).

## Концепция

Bubble Memory — Telegram Mini App для поддержания знаний по ЕГЭ Информатике через простую игровую механику.

> Не выполнять задания. А заботиться о своей памяти.

Ученик заходит в Mini App на 10–30 секунд, кликает по пузырям заданий, которые давно не «трогал», и видит, как его пузырь памяти становится живее.

**Важно (закреплено в v3):** приложение — это именно трекер памяти, а не система проверки знаний. Клик по пузырю — это самоотчёт («я вспомнил / повторил это»), без верификации содержимого. Это осознанное упрощение MVP.

## Механика повторения (утверждено)

Единственное действие пользователя с заданием — **клик по пузырю**:

1. Засчитывается повторение: `repetitions += 1`.
2. `intervalDays` и `nextReview` пересчитываются по фиксированной лестнице интервалов (см. ниже) — без ветки «неверный ответ», её больше нет.
3. Пузырёк красиво перелетает в центральный (недельный) пузырь.
4. Появляется уведомление «Задача добавлена» с отменой действия в течение 2 секунд.
5. **Ограничение:** одно и то же задание засчитывается **не более одного раза в календарный день** — повторный клик в тот же день не двигает `intervalDays`/рейтинг повторно (иначе рейтинг и эволюция пузыря легко накручиваются пустыми кликами). UI при этом может визуально реагировать на клик (лёгкая анимация), просто без изменения состояния памяти.

Лестница интервалов (без изменений от исходного ТЗ):

```
2 → 3 → 5 → 8 → 14 → 21 → 35 → 60 → 90 → 120 дней
```

Архитектура повторения по-прежнему выносится в отдельный модуль (`ReviewAlgorithm`) с простым интерфейсом, чтобы в будущем можно было заменить фиксированную лестницу на SM-2/FSRS **или** добавить обратно градацию качества ответа, если позже решите вернуть проверку заданий:

```ts
interface ReviewAlgorithm {
  computeNext(memory: {
    repetitions: number;
    intervalDays: number;
  }): { intervalDays: number; nextReview: Date; repetitions: number };
}
```

## Главный экран

Один основной экран, минимум текста, максимум анимаций. Состоит из четырёх блоков: верхняя панель, центральный пузырь, история роста, (плюс отдельный экран рейтинга/профиля, доступный по навигации).

---

## Верхняя панель (27 пузырей заданий)

Каждый пузырёк — состояние памяти по одному из заданий ЕГЭ.

Цвет вычисляется автоматически по отношению прошедшего времени к рекомендованному интервалу.

При клике: описано в разделе «Механика повторения».

**Состояния:**
- **Не начато** — `repetitions = 0`, нейтральный/приглушённый цвет, не участвует в общей шкале памяти.
- Обычный цикл — по цветовой таблице ниже.

**Доступность:** так как система полностью цветовая, желательно дублировать статус иконкой/паттерном или показывать точный статус текстом по долгому тапу («повторено 2 дня назад») — не блокирует MVP, но стоит заложить в компонент бабла с самого начала, чтобы не переписывать потом.

---

## Центральный пузырь (неделя)

Живой, «дышащий» пузырь недели. Прогресс — X / target или %.

`targetCount` — динамический: количество заданий, у которых `nextReview` попадает в текущую календарную неделю (плюс ещё не начатые задания, если хотите с первого дня показывать полный охват — на усмотрение дизайна первого экрана для нового пользователя).

При клике по заданию: пузырь увеличивается, волна по поверхности, эффект «буль», уровень наполнения растёт.

---

## История роста (Неделя → Месяц → Год)

**Границы периодов — календарные (утверждено):**
- Неделя — ISO-неделя, понедельник–воскресенье.
- Месяц — календарный месяц.
- Год — календарный год.

Часовой пояс берётся из клиента Telegram WebApp и сохраняется в профиле пользователя — используется для определения начала/конца дня и периода.

Перенос пузыря (неделя → месяц → год) выполняется ежедневной cron-задачей, не завязанной на визит пользователя — иначе при редком открытии приложения переносы «накопятся» и анимация будет выглядеть некорректно.

История не удаляется никогда.

---

## Цвет памяти (утверждено)

| Цвет | Отношение прошедшего времени к `intervalDays` |
|---|---|
| Не начато | `repetitions = 0` |
| Синий | 0–40% |
| Зелёный | 40–70% |
| Жёлтый | 70–100% |
| Оранжевый | 100–150% |
| Красный | 150–300% |
| Чёрный | > 300% |

Пороги — конфиг, легко меняются без редеплоя логики (вынести в отдельный JSON/константы).

**Глобальное состояние памяти** (большой пузырь) — среднее по числовой шкале (0=синий…5=чёрный) по всем заданиям с `repetitions > 0` (задания «не начато» не портят картину новому пользователю).

## Рейтинг

**Публичный.** Любой пользователь может зайти в профиль любого другого («в гости»).

Отображается: никнейм, уровень пузыря, общее количество засчитанных повторений, место в рейтинге.

**Никнейм:**
- Пользователь может задать себе произвольный незанятый никнейм (отдельно от Telegram username/displayName).
- Нужна проверка уникальности на сервере при сохранении (case-insensitive рекомендуется, чтобы «Vasya» и «vasya» не считались разными).
- До того как никнейм задан — можно использовать `displayName`/username из Telegram как значение по умолчанию.

Поскольку рейтинг напрямую зависит от количества кликов, ограничение «одно засчитанное повторение задания в день» (см. «Механика повторения») — обязательная защита от накрутки.

---

## Профиль

Никнейм (редактируемый), текущий уровень пузыря, количество успешных повторений, серия активных дней, история недельных/месячных/годовых пузырей.

Плюс: настройки уведомлений (вкл/выкл, время), часовой пояс (определяется автоматически из Telegram, с возможностью переопределить).

---

## Преподаватель / модерация

**Не реализуется в MVP.** Поскольку профили публичны и открыты для просмотра всем, отдельная роль/права доступа не нужны на этом этапе. Поле `role` в модели `User` можно оставить в схеме на будущее (не используется в логике сейчас), чтобы не переделывать миграции, если роль понадобится позже.

---

## Безопасность и приватность

- **Валидация `initData`** — обязательна для всех запросов (см. «Технологии»).
- **Хостинг в РФ** — подтверждено.
- **Экран согласия на обработку персональных данных** — обязателен перед публичным запуском, но **не блокирует текущую разработку**: продукт сейчас для внутреннего использования (закрытый круг пользователей). Рекомендация: сделать простую модалку/шаг онбординга с чекбоксом согласия, реализовать в последнюю очередь перед открытием доступа шире текущего круга. Занести в бэклог явным пунктом, чтобы не забыть.
- Поскольку рейтинг и профили публичны, а аудитория может включать несовершеннолетних — никнейм не обязан совпадать с реальным именем, это дополнительно снижает риски приватности (уже учтено выше).

## Направление дизайна

Игровой, погружающий стиль — приоритет у ощущения «живого» пузыря, а не у утилитарного трекера. Ориентиры для проработки на этапе визуального дизайна:
- глубина и свет (мягкие градиенты, свечение, полупрозрачность «стекла»/«воды»);
- физика движения (инерция, пружины Framer Motion, а не линейные transition);
- отклик на каждое действие — даже мелкий клик должен ощущаться «вкусно» (микро-анимация + лёгкий импульс на пузыре);
- по возможности — лёгкая тактильная обратная связь через Telegram Haptic Feedback API при клике по баблу (усиливает ощущение «живости» почти бесплатно с точки зрения разработки).

## MVP — итоговый чек-лист

- авторизация через Telegram + валидация `initData`;
- главный экран с 27 бабл-заданиями;
- клик = засчитанное повторение (1 раз в день на задание), без банка заданий и проверки ответов;
- недельный пузырь с динамическим `targetCount`;
- интервальное повторение по фиксированной лестнице;
- автосмена цвета памяти по утверждённым порогам;
- история недель/месяцев/годов, календарные границы, cron-перенос;
- эволюция пузыря по утверждённым тирам;
- публичный рейтинг с уникальными никнеймами;
- профиль (никнейм, статистика, настройки уведомлений);
- Telegram-бот с уведомлениями (лимит частоты, deep link, идемпотентность);
- хостинг в РФ;
- *(в самом конце, перед расширением аудитории)* экран согласия на обработку персональных данных.

Роль преподавателя/админка — сознательно исключена из MVP.
